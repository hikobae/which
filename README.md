# which

which - `which` clone for windows

## Usage

```
which [-h | --help] [-v | --version] filename
```

`filename` を、カレントディレクトリと `PATH` の各ディレクトリから探し、
見つかったファイルのパスをすべて出力する。

- `-h`, `--help` : 使い方を表示して終了する。
- `-v`, `--version` : バージョンを表示して終了する。

上記以外の引数は、`-` で始まるものも含めてすべて `filename` として扱う
(未知のオプションはエラーにならない)。
`-h` や `-v` という名前のファイルは検索できない。`--` による区切りにも対応していない。
`-h` / `-v` と `filename` を同時に指定した場合は、`filename` を無視して
ヘルプ (`-h`) またはバージョン (`-v`) の表示を優先する。
`filename` は UTF-8 で指定する。非 UTF-8 の引数には対応していない。

### 終了コード

| コード | 意味 |
|---|---|
| 0 | 1 件以上見つかった (またはヘルプ・バージョン表示) |
| 1 | 見つからなかった、または引数・環境変数のエラー |

## Behavior

### 検索順序

1. カレントディレクトリ
2. `PATH` の先頭から順に各ディレクトリ

各ディレクトリで、拡張子なし、続いて `PATHEXT` の各拡張子の順に調べる。
(例: `PATHEXT=.COM;.EXE` なら `foo`、`foo.com`、`foo.exe`)

### 環境変数

- `PATH`: 未設定の場合はエラー終了する。非 UTF-8 のエントリが含まれていても、そのエントリを
  そのまま扱って検索を続ける。
- `PATHEXT`: 未設定の場合は空として扱い、拡張子の補完をしない。非 UTF-8 の値の場合はエラー終了する。
- `PATH` / `PATHEXT` ともに、各エントリの前後の空白は除去し、空のエントリは無視する
  (前後に空白を含むディレクトリ名や拡張子は扱えない)。
- `PATHEXT` の拡張子は小文字に変換して照合する。

### 全件出力

最初の 1 件で止まらず、見つかったものをすべて出力する (`where` コマンドや
`which -a` 相当)。

### 重複の扱い

同じファイルが複数の経路で見つかった場合、 **最初に見つかった 1 件だけ**
を出力する。 同一かどうかは、パスを正規化 (`canonicalize`)
した結果で判定する。このため、次のものは 1 件にまとまる。

- `PATH` に同じディレクトリが複数回、または大文字小文字違いで含まれる場合
- カレントディレクトリが `PATH` にも含まれる場合
- シンボリックリンクやジャンクションを経由して、同じ実体を指す場合

出力されるのは、最初に見つかった時点の表記 (正規化前のパス) になる。
